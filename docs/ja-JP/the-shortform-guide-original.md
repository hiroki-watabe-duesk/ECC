## スキルとコマンド

スキルはルールのように機能し、特定のスコープやワークフローに制約されています。特定のワークフローを実行する必要があるときの、プロンプトへのショートハンド（短縮表現）です。

Opus 4.5 で長いコーディングセッションを終えたあと、デッドコードや散らかった .md ファイルを片付けたい?

`/refactor-clean` を実行しましょう。テストが必要? `/tdd`、`/e2e`、`/test-coverage`。スキルとコマンドは一つのプロンプトの中で連鎖（chain）させられます。

私は、チェックポイントごとにコードマップ（codemap）を更新するスキルを作ることができます —— これは、Claudeが探索にコンテキストを浪費せずに、あなたのコードベースを素早く把握するための手段です。

### ~/.claude/skills/codemap-updater.md

コマンドはスラッシュコマンド経由で実行されるスキルです。両者は重なりますが、保存場所が異なります。

- スキル: ~/.claude/skills —— より広範なワークフロー定義

- コマンド: ~/.claude/commands —— 素早く実行できるプロンプト

## フック（Hooks）

フックは、特定のイベントで発火するトリガーベースの自動化です。スキルとは異なり、ツール呼び出しとライフサイクルイベントに制約されています。

### フックの種類

1. PreToolUse —— ツールが実行される前（検証、リマインダー）

1. PostToolUse —— ツールが完了したあと（フォーマット、フィードバックループ）

1. UserPromptSubmit —— メッセージを送ったとき

1. Stop —— Claudeが応答を終えたとき

1. PreCompact —— コンテキストのコンパクト前

1. Notification —— 権限リクエスト

### 例: 長時間実行コマンドの前の tmux リマインダー

ヒント: JSONを手書きする代わりに、`hookify` プラグインを使って会話形式でフックを作りましょう。`/hookify` を実行して、やりたいことを説明してください。

## サブエージェント

サブエージェントは、あなたのオーケストレーター（メインのClaude）が限定されたスコープでタスクを委任できるプロセスです。バックグラウンドでもフォアグラウンドでも実行でき、メインエージェントのコンテキストを解放します。

サブエージェントはスキルとうまく連携します —— あなたのスキルのサブセットを実行できるサブエージェントにタスクを委任すれば、それらのスキルを自律的に使えます。特定のツール権限でサンドボックス化することもできます。

適切なスコープ設定のため、サブエージェントごとに許可するツール・MCP・権限を設定しましょう。

## ルールとメモリ

`.rules` フォルダには、Claudeが「常に」従うべきベストプラクティスを記した `.md` ファイルが入ります。2つのアプローチがあります。

1. 単一の CLAUDE.md —— すべてを1つのファイルに（ユーザーまたはプロジェクトレベル）

1. ルールフォルダ —— 関心事ごとにグループ分けされたモジュール化された `.md` ファイル

### ルールの例

- コードベースに絵文字を使わない

- フロントエンドで紫系の色合いを避ける

- デプロイ前に必ずコードをテストする

- メガファイルよりモジュール化されたコードを優先する

- console.log を決してコミットしない

## MCP（Model Context Protocol）

MCPはClaudeを外部サービスへ直接接続します。APIの代替ではなく —— それらを取り巻くプロンプト駆動のラッパーであり、情報をたどる際の柔軟性を高めます。

例: Supabase MCP を使えば、Claudeはコピー＆ペーストなしに特定のデータを引き出し、上流で直接SQLを実行できます。データベースやデプロイプラットフォームなどでも同様です。

Chrome in Claude: は、Claudeがあなたのブラウザを自律的に操作できる組み込みのプラグインMCPです —— あちこちクリックして、物事がどう動くかを確かめます。

### 重要: コンテキストウィンドウの管理

MCPは厳選してください。私はすべてのMCPをユーザー設定に入れていますが、使っていないものはすべて無効にしています。`/plugins` に移動して下にスクロールするか、`/mcp` を実行します。

コンパクト前の200kのコンテキストウィンドウも、ツールを有効にしすぎると実質70kしかないかもしれません。パフォーマンスは著しく低下します。

経験則: 設定には20〜30個のMCPを持ちつつ、有効化は10個未満／アクティブなツールは80個未満に保つこと。

## プラグイン

プラグインは、面倒な手動セットアップの代わりに、ツールを簡単にインストールできるようパッケージ化したものです。プラグインは、スキル + MCP の組み合わせでも、フック/ツールをまとめたものでも構いません。

### プラグインのインストール

LSPプラグイン: は、Claude Codeをエディタの外で頻繁に走らせる人に特に有用です。Language Server Protocol により、IDEを開かなくても、Claudeにリアルタイムの型チェック・定義へのジャンプ・賢い補完が得られます。

MCPと同じ警告 —— コンテキストウィンドウに注意。

## ヒントとコツ

### キーボードショートカット

- Ctrl+U —— 行全体を削除（backspace連打より速い）

- ! —— bashコマンドの簡易プレフィックス

- @ —— ファイルを検索

- / —— スラッシュコマンドを起動

- Shift+Enter —— 複数行入力

- Tab —— 思考表示の切り替え

- Esc Esc —— Claudeを中断／コードを復元

### 並列ワークフロー

/fork —— キューに溜まるメッセージを連投する代わりに、会話をフォークして重複しないタスクを並列で行う

Git Worktree —— 競合なしに重複する並列Claudeを動かすため。各worktreeは独立したチェックアウト

長時間実行コマンドのための tmux: Claudeが実行するログ/bashプロセスをストリーミングして監視する

mgrep > grep: `mgrep` は ripgrep/grep からの大きな改善です。プラグインマーケットプレイス経由でインストールし、`/mgrep` スキルを使います。ローカル検索とWeb検索の両方で機能します。

### その他の便利なコマンド

- /rewind —— 以前の状態に戻る

- /statusline —— ブランチ、コンテキスト%、TODO でカスタマイズ

- /checkpoints —— ファイルレベルのアンドゥポイント

- /compact —— 手動でコンテキストのコンパクトをトリガー

### GitHub Actions による CI/CD

GitHub Actions でPRのコードレビューをセットアップします。設定すれば、ClaudeはPRを自動でレビューできます。

### サンドボックス化

リスクのある操作にはサンドボックスモードを使います —— Claudeは制限された環境で実行され、実際のシステムに影響しません。（`--dangerously-skip-permissions` を使うとこれと逆になり、Claudeを自由に動き回らせます。注意しないと破壊的になりえます。）

## エディタについて

エディタは必須ではありませんが、Claude Codeのワークフローに良くも悪くも影響しえます。Claude Codeはどのターミナルからでも動作しますが、有能なエディタと組み合わせると、リアルタイムのファイル追跡、素早いナビゲーション、統合されたコマンド実行が解放されます。

### Zed（私の好み）

私は Zed を使っています —— Rust製の、軽量で高速、高度にカスタマイズ可能なエディタです。

### なぜ Zed が Claude Code とうまく合うのか

- Agent Panel 統合 —— Zed の Claude 統合により、Claudeが編集する際にファイル変更をリアルタイムで追跡できます。Claudeが参照するファイル間を、エディタを離れずに行き来できます

- パフォーマンス —— Rustで書かれており、瞬時に開き、大規模なコードベースを遅延なく扱えます

- CMD+Shift+R コマンドパレット —— すべてのカスタムスラッシュコマンド・デバッガ・ツールへ、検索可能なUIで素早くアクセス。ターミナルに切り替えずにちょっとしたコマンドを走らせたいときにも

- 最小限のリソース使用 —— 重い操作の最中にシステムリソースをClaudeと奪い合いません

- Vimモード —— それが好みなら、完全なvimキーバインド

1. 画面を分割する —— 片側にClaude Codeのターミナル、もう片側にエディタを置く

1. Ctrl + G —— Claudeが現在作業しているファイルを Zed で素早く開く

1. オートセーブ —— Claudeのファイル読み込みが常に最新になるよう、オートセーブを有効にする

1. Git統合 —— エディタのgit機能を使って、コミット前にClaudeの変更をレビューする

1. ファイルウォッチャー —— 多くのエディタは変更されたファイルを自動リロードします。これが有効になっているか確認する

### VSCode / Cursor

これも有効な選択肢で、Claude Codeとうまく機能します。ターミナル形式で使い、`\ide` でエディタと自動同期して LSP 機能を有効にできます（今やプラグインとやや冗長ではあります）。あるいは、エディタとより統合され、UIも揃った拡張機能を選ぶこともできます。

## 重要なポイント

1. 複雑にしすぎない —— 設定はアーキテクチャではなくファインチューニングだと捉える
