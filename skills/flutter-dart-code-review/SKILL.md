# Flutter/Dart コードレビューベストプラクティス

Flutter/Dartアプリケーションをレビューするための包括的なライブラリ非依存チェックリスト。これらの原則は、使用する状態管理ソリューション、ルーティングライブラリ、DIフレームワークに関係なく適用されます。

---

## 1. プロジェクト全体の健全性

- [ ] プロジェクトが一貫したフォルダ構造に従っている（機能優先またはレイヤー優先）
- [ ] 関心の適切な分離：UI、ビジネスロジック、データレイヤー
- [ ] ウィジェットにビジネスロジックが含まれていない。ウィジェットは純粋にプレゼンテーション用
- [ ] `pubspec.yaml` が整理されている。未使用の依存関係がなく、バージョンが適切に固定されている
- [ ] `analysis_options.yaml` に厳格なアナライザー設定を有効にした厳格なlintセットが含まれている
- [ ] 本番コードに `print()` 文がない。`dart:developer` の `log()` またはloggingパッケージを使用する
- [ ] 生成ファイル（`.g.dart`、`.freezed.dart`、`.gr.dart`）が最新か `.gitignore` に含まれている
- [ ] プラットフォーム固有のコードが抽象化の背後に分離されている

## 2. Dart言語の落とし穴

- [ ] **暗黙のdynamic**: 型注釈の欠如による `dynamic` への推論。`strict-casts`、`strict-inference`、`strict-raw-types` を有効にする
- [ ] **Nullセーフティの誤用**: 適切なnullチェックやDart 3のパターンマッチング（`if (value case var v?)`）の代わりに `!`（bangオペレータ）を過度に使用
- [ ] **型昇格の失敗**: ローカル変数の昇格が機能するところで `this.field` を使用している
- [ ] **広すぎるキャッチ**: `on` 句のない `catch (e)`。常に例外の型を指定する
- [ ] **`Error` のキャッチ**: `Error` のサブタイプはバグを示すためキャッチすべきではない
- [ ] **不要な `async`**: `await` を一度も行わないのに `async` とマークされた関数。不要なオーバーヘッド
- [ ] **`late` の過剰使用**: nullable またはコンストラクタ初期化の方が安全な場所で `late` を使用している。エラーをランタイムに先送りする
- [ ] **ループ内の文字列連結**: 反復的な文字列構築には `+` の代わりに `StringBuffer` を使用する
- [ ] **`const` コンテキストでのミュータブルな状態**: `const` コンストラクタクラスのフィールドはミュータブルにすべきでない
- [ ] **`Future` 戻り値の無視**: `await` を使用するか、意図を示すために明示的に `unawaited()` を呼び出す
- [ ] **`final` が使えるのに `var` を使用**: ローカル変数には `final`、コンパイル時定数には `const` を優先する
- [ ] **相対インポート**: 一貫性のために `package:` インポートを使用する
- [ ] **ミュータブルなコレクションの公開**: パブリックAPIは生の `List`/`Map` ではなく変更不可能なビューを返すべき
- [ ] **Dart 3パターンマッチングの未使用**: 冗長な `is` チェックと手動キャストの代わりにswitch式と `if-case` を優先する
- [ ] **複数の戻り値のための使い捨てクラス**: 単一用途のDTOの代わりにDart 3のレコード `(String, int)` を使用する
- [ ] **本番コードでの `print()`**: `dart:developer` の `log()` またはプロジェクトのloggingパッケージを使用する。`print()` はログレベルがなくフィルタリングできない

## 3. ウィジェットのベストプラクティス

### ウィジェットの分解:
- [ ] `build()` メソッドが約80〜100行を超えるウィジェットがない
- [ ] カプセル化と変更方法（リビルド境界）の両方によってウィジェットが分割されている
- [ ] ウィジェットを返すプライベートな `_build*()` ヘルパーメソッドが別のウィジェットクラスに抽出されている（要素の再利用、const伝播、フレームワーク最適化を可能にする）
- [ ] ミュータブルなローカル状態が不要な場合はStatelessウィジェットを優先している
- [ ] 再利用可能な場合、抽出したウィジェットは別のファイルにある

### Constの使用:
- [ ] 不要なリビルドを防ぐため、可能な限り `const` コンストラクタを使用している
- [ ] 変更されないコレクションに `const` リテラルを使用している（`const []`、`const {}`）
- [ ] すべてのフィールドがfinalの場合、コンストラクタが `const` として宣言されている

### Keyの使用:
- [ ] リスト/グリッドで並べ替え時の状態保持のために `ValueKey` を使用している
- [ ] `GlobalKey` はツリーを跨いで状態にアクセスする必要が本当にある場合にのみ控えめに使用している
- [ ] `UniqueKey` は `build()` 内で避けている。毎フレームリビルドを強制する
- [ ] 単一の値ではなくデータオブジェクトに基づいてIDを決定する場合に `ObjectKey` を使用している

### テーマとデザインシステム:
- [ ] 色は `Theme.of(context).colorScheme` から取得している。`Colors.red` やhex値はハードコードしない
- [ ] テキストスタイルは `Theme.of(context).textTheme` から取得している。生のフォントサイズを持つインラインの `TextStyle` はない
- [ ] ダークモードの互換性を確認している。ライト背景の前提がない
- [ ] スペースとサイズはマジックナンバーではなく一貫したデザイントークンまたは定数を使用している

### buildメソッドの複雑さ:
- [ ] `build()` 内でネットワーク呼び出し、ファイルI/O、重い計算を行っていない
- [ ] `build()` 内で `Future.then()` や `async` 処理を行っていない
- [ ] `build()` 内でサブスクリプションの作成（`.listen()`）を行っていない
- [ ] `setState()` は可能な限り小さなサブツリーに局所化されている

## 4. 状態管理（ライブラリ非依存）

これらの原則はすべてのFlutter状態管理ソリューション（BLoC、Riverpod、Provider、GetX、MobX、Signals、ValueNotifierなど）に適用されます。

### アーキテクチャ:
- [ ] ビジネスロジックはウィジェット層の外側、状態管理コンポーネント（BLoC、Notifier、Controller、Store、ViewModelなど）に存在する
- [ ] 状態管理コンポーネントは内部でコンストラクトするのではなく、インジェクションを通じて依存関係を受け取る
- [ ] サービスまたはリポジトリ層がデータソースを抽象化する。ウィジェットと状態管理コンポーネントはAPIやデータベースを直接呼び出さない
- [ ] 状態管理コンポーネントは単一の責任を持つ。無関係な関心事を扱う「神」のような管理コンポーネントはない
- [ ] コンポーネント間の依存関係がソリューションの規約に従っている:
  - **Riverpod**では: プロバイダーが `ref.watch` を通じて他のプロバイダーに依存することは想定内。循環または過度に複雑なチェーンのみフラグを立てる
  - **BLoC**では: blocは他のblocに直接依存すべきでない。共有リポジトリかプレゼンテーション層の協調を優先する
  - その他のソリューションでは: コンポーネント間通信の文書化された規約に従う

### 不変性と値の同一性（不変状態ソリューション向け: BLoC、Riverpod、Redux）:
- [ ] 状態オブジェクトは不変。`copyWith()` またはコンストラクタで新しいインスタンスを作成し、インプレースで変更しない
- [ ] 状態クラスが `==` と `hashCode` を適切に実装している（比較にすべてのフィールドが含まれている）
- [ ] メカニズムがプロジェクト全体で一貫している。手動オーバーライド、`Equatable`、`freezed`、Dartレコード、またはその他
- [ ] 状態オブジェクト内のコレクションが生のミュータブルな `List`/`Map` として公開されていない

### リアクティビティの規律（リアクティブな変更ソリューション向け: MobX、GetX、Signals）:
- [ ] 状態はソリューションのリアクティブAPI（MobXの `@action`、signalsの `.value`、GetXの `.obs`）を通じてのみ変更される。直接のフィールド変更は変更追跡を回避する
- [ ] 派生値はソリューションの計算メカニズムを使用し、冗長に格納されない
- [ ] リアクションとdisposerが適切にクリーンアップされている（MobXの `ReactionDisposer`、Signalsのエフェクトクリーンアップ）

### 状態形状の設計:
- [ ] 相互に排他的な状態は、sealedタイプ、ユニオンバリアント、またはソリューション組み込みの非同期状態タイプ（RiverpodのAsyncValueなど）を使用する。ブールフラグ（`isLoading`、`isError`、`hasData`）は使用しない
- [ ] すべての非同期操作がロード中、成功、エラーを別個の状態としてモデル化している
- [ ] すべての状態バリアントがUIで網羅的に処理されている。サイレントに無視されるケースがない
- [ ] エラー状態は表示のためにエラー情報を持つ。ロード中状態は古いデータを持たない
- [ ] nullableデータをロードインジケーターとして使用していない。状態は明示的

```dart
// BAD — ブールフラグの乱用により不可能な状態が表現可能になる
class UserState {
  bool isLoading = false;
  bool hasError = false; // isLoading && hasError が表現可能!
  User? user;
}

// GOOD (不変アプローチ) — sealedタイプで不可能な状態を表現不可能にする
sealed class UserState {}
class UserInitial extends UserState {}
class UserLoading extends UserState {}
class UserLoaded extends UserState {
  final User user;
  const UserLoaded(this.user);
}
class UserError extends UserState {
  final String message;
  const UserError(this.message);
}

// GOOD (リアクティブアプローチ) — observableなenum + データ、リアクティビティAPIを通じた変更
// enum UserStatus { initial, loading, loaded, error }
// ソリューションのobservable/signalを使用してstatusとdataを別々にラップする
```

### リビルドの最適化:
- [ ] 状態コンシューマーウィジェット（Builder、Consumer、Observer、Obx、Watchなど）が可能な限り狭いスコープに限定されている
- [ ] セレクターを使用して、すべての状態エミッションではなく特定のフィールドが変更された場合にのみリビルドされる
- [ ] `const` ウィジェットがツリーを通じたリビルドの伝播を停止するために使用されている
- [ ] 計算/派生状態がリアクティブに計算され、冗長に格納されない

### サブスクリプションとdisposal:
- [ ] すべての手動サブスクリプション（`.listen()`）が `dispose()` / `close()` でキャンセルされている
- [ ] ストリームコントローラーが不要になった時点でクローズされている
- [ ] タイマーがdisposalライフサイクルでキャンセルされている
- [ ] 手動サブスクリプションよりフレームワーク管理のライフサイクルが優先されている（`.listen()` より宣言的ビルダー）
- [ ] 非同期コールバックで `setState` の前に `mounted` チェックがある
- [ ] `mounted` なしに `await` の後で `BuildContext` を使用していない（Flutter 3.7以降）。古いコンテキストはクラッシュを引き起こす（`context.mounted` を確認）
- [ ] 非同期ギャップの後、ウィジェットがまだマウントされていることを確認せずにナビゲーション、ダイアログ、またはscaffoldメッセージを行っていない
- [ ] `BuildContext` がシングルトン、状態管理コンポーネント、または静的フィールドに格納されていない

### ローカル状態とグローバル状態:
- [ ] 一時的なUI状態（チェックボックス、スライダー、アニメーション）はローカル状態（`setState`、`ValueNotifier`）を使用する
- [ ] 共有状態は必要な高さにのみ持ち上げられている。過度にグローバル化しない
- [ ] 機能スコープの状態は機能がアクティブでなくなった時点で適切にdisposalされる

## 5. パフォーマンス

### 不要なリビルド:
- [ ] ルートウィジェット級で `setState()` を呼び出していない。状態変更を局所化する
- [ ] `const` ウィジェットがリビルドの伝播を停止するために使用されている
- [ ] `RepaintBoundary` が独立して再描画する複雑なサブツリーの周囲に使用されている
- [ ] `AnimatedBuilder` のchildパラメーターがアニメーションから独立したサブツリーに使用されている

### build()内の重い処理:
- [ ] `build()` 内で大きなコレクションのソート、フィルタリング、またはマッピングを行っていない。状態管理層で計算する
- [ ] `build()` 内でregexのコンパイルを行っていない
- [ ] `MediaQuery.of(context)` の使用が具体的（例：`MediaQuery.sizeOf(context)`）

### 画像の最適化:
- [ ] ネットワーク画像がキャッシュを使用している（プロジェクトに適したキャッシュソリューション）
- [ ] ターゲットデバイスに適した画像解像度（サムネイルに4K画像をロードしない）
- [ ] 表示サイズでデコードするために `cacheWidth`/`cacheHeight` を使用した `Image.asset`
- [ ] ネットワーク画像にplaceholderとエラーウィジェットが提供されている

### 遅延ロード:
- [ ] 大きいまたは動的なリストには `ListView(children: [...])` の代わりに `ListView.builder` / `GridView.builder` を使用している（小さく静的なリストには具体的なコンストラクタで問題ない）
- [ ] 大きなデータセットにページネーションが実装されている
- [ ] Webビルドで重いライブラリに遅延ロード（`deferred as`）を使用している

### その他:
- [ ] アニメーションに `Opacity` ウィジェットを避けている。`AnimatedOpacity` または `FadeTransition` を使用する
- [ ] アニメーションにクリッピングを避けている。事前に画像をクリップする
- [ ] ウィジェットで `operator ==` をオーバーライドしていない。代わりに `const` コンストラクタを使用する
- [ ] 固有次元ウィジェット（`IntrinsicHeight`、`IntrinsicWidth`）を控えめに使用している（追加のレイアウトパス）

## 6. テスト

### テストの種類と期待値:
- [ ] **ユニットテスト**: すべてのビジネスロジック（状態管理コンポーネント、リポジトリ、ユーティリティ関数）をカバー
- [ ] **ウィジェットテスト**: 個々のウィジェットの動作、インタラクション、ビジュアル出力をカバー
- [ ] **統合テスト**: 重要なユーザーフローをエンドツーエンドでカバー
- [ ] **ゴールデンテスト**: デザインクリティカルなUIコンポーネントのピクセルパーフェクトな比較

### カバレッジ目標:
- [ ] ビジネスロジックで80%以上の行カバレッジを目指す
- [ ] すべての状態遷移に対応するテストがある（ローディング→成功、ローディング→エラー、リトライなど）
- [ ] エッジケースのテスト：空の状態、エラー状態、ローディング状態、境界値

### テストの分離:
- [ ] 外部依存関係（APIクライアント、データベース、サービス）がモック化またはフェイク化されている
- [ ] 各テストファイルが正確に1つのクラス/ユニットをテストしている
- [ ] テストが実装の詳細ではなく動作を検証している
- [ ] スタブが各テストに必要な動作のみを定義している（最小限のスタビング）
- [ ] テストケース間で共有されたミュータブルな状態がない

### ウィジェットテストの品質:
- [ ] `pumpWidget` と `pump` が非同期操作に正しく使用されている
- [ ] `find.byType`、`find.text`、`find.byKey` が適切に使用されている
- [ ] タイミングに依存したフラキーなテストがない。`pumpAndSettle` または明示的な `pump(Duration)` を使用する
- [ ] テストがCIで実行され、失敗がマージをブロックする

## 7. アクセシビリティ

### セマンティックウィジェット:
- [ ] 自動ラベルが不十分な場合に `Semantics` ウィジェットがスクリーンリーダーラベルを提供するために使用されている
- [ ] 純粋に装飾的な要素に `ExcludeSemantics` が使用されている
- [ ] 関連するウィジェットを単一のアクセス可能な要素に結合するために `MergeSemantics` が使用されている
- [ ] 画像に `semanticLabel` プロパティが設定されている

### スクリーンリーダーサポート:
- [ ] すべてのインタラクティブな要素がフォーカス可能で意味のある説明を持つ
- [ ] フォーカス順序が論理的（視覚的な読み取り順序に従う）

### ビジュアルアクセシビリティ:
- [ ] テキストと背景のコントラスト比が4.5:1以上
- [ ] タップ可能なターゲットが少なくとも48x48ピクセル
- [ ] 色だけが状態のインジケーターでない（アイコン/テキストを併用する）
- [ ] テキストがシステムフォントサイズ設定に合わせてスケールする

### インタラクションのアクセシビリティ:
- [ ] ノーオプな `onPressed` コールバックがない。すべてのボタンは何かを実行するか無効化されている
- [ ] エラーフィールドが修正案を提示する
- [ ] ユーザーがデータを入力中に予期せずコンテキストが変更されない

## 8. プラットフォーム固有の考慮事項

### iOS/Androidの違い:
- [ ] 適切な場合にプラットフォームアダプティブウィジェットが使用されている
- [ ] バックナビゲーションが正しく処理されている（Androidの戻るボタン、iOSのスワイプバック）
- [ ] ステータスバーとセーフエリアが `SafeArea` ウィジェットで処理されている
- [ ] プラットフォーム固有の権限が `AndroidManifest.xml` と `Info.plist` に宣言されている

### レスポンシブデザイン:
- [ ] レスポンシブレイアウトに `LayoutBuilder` または `MediaQuery` が使用されている
- [ ] ブレークポイントが一貫して定義されている（スマートフォン、タブレット、デスクトップ）
- [ ] 小さな画面でテキストがオーバーフローしない。`Flexible`、`Expanded`、`FittedBox` を使用する
- [ ] 横向きの向きがテストされているか明示的にロックされている
- [ ] Web固有: マウス/キーボードインタラクションがサポートされ、ホバー状態が存在する

## 9. セキュリティ

### セキュアストレージ:
- [ ] 機密データ（トークン、資格情報）がプラットフォームセキュアストレージを使用して保存されている（iOSのKeychain、AndroidのEncryptedSharedPreferences）
- [ ] 秘密情報をプレーンテキストストレージに保存しない
- [ ] 機密性の高い操作に対して生体認証ゲーティングが考慮されている

### APIキーの取り扱い:
- [ ] APIキーがDartソースにハードコードされていない。`--dart-define`、VCSから除外された `.env` ファイル、またはコンパイル時設定を使用する
- [ ] 秘密情報がgitにコミットされていない。`.gitignore` を確認する
- [ ] 本当に秘密のキーにはバックエンドプロキシを使用する（クライアントはサーバーの秘密を保持すべきでない）

### 入力バリデーション:
- [ ] すべてのユーザー入力がAPIに送信される前にバリデーションされている
- [ ] フォームバリデーションが適切なバリデーションパターンを使用している
- [ ] ユーザー入力の生のSQLや文字列補間がない
- [ ] ディープリンクのURLがナビゲーション前にバリデーションおよびサニタイズされている

### ネットワークセキュリティ:
- [ ] すべてのAPI呼び出しにHTTPSが強制されている
- [ ] 高セキュリティアプリに証明書ピンニングが考慮されている
- [ ] 認証トークンが適切にリフレッシュされ期限切れになる
- [ ] 機密データがログに記録またはプリントされていない

## 10. パッケージ/依存関係のレビュー

### pub.devパッケージの評価:
- [ ] **pubポイントスコア**を確認する（130+/160を目指す）
- [ ] コミュニティシグナルとして **likes** と **popularity** を確認する
- [ ] パブリッシャーがpub.devで**verified**であることを確認する
- [ ] 最終公開日を確認する。古いパッケージ（1年以上）はリスク
- [ ] オープンイシューとメンテナーの対応時間を確認する
- [ ] プロジェクトとのライセンス互換性を確認する
- [ ] プラットフォームサポートがターゲットをカバーしていることを確認する

### バージョン制約:
- [ ] 依存関係にキャレット構文（`^1.2.3`）を使用する。互換性のある更新を許可する
- [ ] 絶対に必要な場合にのみ正確なバージョンを固定する
- [ ] 古くなった依存関係を追跡するために定期的に `flutter pub outdated` を実行する
- [ ] 本番の `pubspec.yaml` に依存関係のオーバーライドがない。コメント/イシューリンク付きの一時的な修正にのみ使用
- [ ] 推移的依存関係の数を最小化する。各依存関係は攻撃対象領域

### モノレポ固有（melos/workspace）:
- [ ] 内部パッケージはパブリックAPIからのみインポートする。`package:other/src/internal.dart` は使用しない（Dartパッケージのカプセル化を壊す）
- [ ] 内部パッケージの依存関係はハードコードされた `path: ../../` 相対文字列ではなくworkspace解決を使用する
- [ ] すべてのサブパッケージがルートの `analysis_options.yaml` を共有または継承している

## 11. ナビゲーションとルーティング

### 一般原則（任意のルーティングソリューションに適用）:
- [ ] 1つのルーティングアプローチが一貫して使用されている。命令的な `Navigator.push` と宣言的ルーターを混在させない
- [ ] ルート引数が型付きである。`Map<String, dynamic>` または `Object?` へのキャストがない
- [ ] ルートパスが定数、enum、または生成されたものとして定義されている。コード全体に散らばったマジック文字列がない
- [ ] 認証ガード/リダイレクトが集中管理されている。個々の画面に重複していない
- [ ] AndroidとiOSの両方でディープリンクが設定されている
- [ ] ディープリンクのURLがナビゲーション前にバリデーションおよびサニタイズされている
- [ ] ナビゲーション状態がテスト可能である。ルートの変更をテストで検証できる
- [ ] バック動作がすべてのプラットフォームで正しい

## 12. エラー処理

### フレームワークのエラー処理:
- [ ] フレームワークエラー（build、layout、paint）をキャプチャするために `FlutterError.onError` がオーバーライドされている
- [ ] Flutterでキャッチされない非同期エラーに `PlatformDispatcher.instance.onError` が設定されている
- [ ] リリースモードで `ErrorWidget.builder` がカスタマイズされている（赤い画面の代わりにユーザーフレンドリー）
- [ ] `runApp` の周囲にグローバルエラーキャプチャラッパーがある（例：`runZonedGuarded`、Sentry/Crashlyticsラッパー）

### エラーレポート:
- [ ] エラーレポートサービスが統合されている（Firebase Crashlytics、Sentryなど）
- [ ] スタックトレースと共に致命的でないエラーが報告されている
- [ ] 状態管理のエラーオブザーバーがエラーレポートに接続されている（例：BlocObserver、ProviderObserver、またはソリューションの同等物）
- [ ] デバッグのためにエラーレポートにユーザー識別情報（ユーザーID）が添付されている

### グレースフルデグラデーション:
- [ ] APIエラーがクラッシュではなくユーザーフレンドリーなエラーUIになっている
- [ ] 一時的なネットワーク障害のリトライメカニズムがある
- [ ] オフライン状態が適切に処理されている
- [ ] 状態管理のエラー状態が表示のためにエラー情報を持っている
- [ ] 生の例外（ネットワーク、パース）がUIに到達する前にユーザーフレンドリーなローカライズされたメッセージにマッピングされている。生の例外文字列をユーザーに表示しない

## 13. 国際化（l10n）

### セットアップ:
- [ ] ローカライゼーションソリューションが設定されている（FlutterのビルトインARB/l10n、easy_localizationなど）
- [ ] サポートされているロケールがアプリ設定に宣言されている

### コンテンツ:
- [ ] すべてのユーザーに見えるフィールドがローカライゼーションシステムを使用している。ウィジェットにハードコードされた文字列がない
- [ ] テンプレートファイルに翻訳者向けの説明/コンテキストが含まれている
- [ ] 複数形、性別、セレクトにICUメッセージ構文が使用されている
- [ ] プレースホルダーが型付きで定義されている
- [ ] ロケール間でキーの欠落がない

### コードレビュー:
- [ ] ローカライゼーションアクセサーがプロジェクト全体で一貫して使用されている
- [ ] 日付、時刻、数値、通貨のフォーマットがロケールを考慮している
- [ ] アラビア語、ヘブライ語などをターゲットにする場合はテキストの方向性（RTL）がサポートされている
- [ ] ローカライズされたテキストに文字列連結を使用していない。パラメータ化されたメッセージを使用する

## 14. 依存性注入

### 原則（任意のDIアプローチに適用）:
- [ ] クラスがレイヤー境界で具体的な実装ではなく抽象（インターフェース）に依存している
- [ ] 依存関係がコンストラクタ、DIフレームワーク、またはプロバイダーグラフを通じて外部から提供されている。内部で作成されていない
- [ ] 登録がライフタイムを区別している：シングルトンvsファクトリvs遅延シングルトン
- [ ] 環境固有のバインディング（dev/staging/prod）がランタイムの `if` チェックではなく設定を使用している
- [ ] DIグラフに循環依存関係がない
- [ ] サービスロケーター呼び出し（使用する場合）がビジネスロジック全体に散らばっていない

## 15. 静的解析

### 設定:
- [ ] `analysis_options.yaml` が厳格な設定を有効にして存在する
- [ ] 厳格なアナライザー設定：`strict-casts: true`、`strict-inference: true`、`strict-raw-types: true`
- [ ] 包括的なlintルールセットが含まれている（very_good_analysis、flutter_lints、またはカスタム厳格ルール）
- [ ] モノレポ内のすべてのサブパッケージがルートの解析オプションを継承または共有している

### 強制:
- [ ] コミットされたコードにアナライザーの未解決の警告がない
- [ ] Lint抑制（`// ignore:`）が理由を説明するコメントで正当化されている
- [ ] `flutter analyze` がCIで実行され、失敗がマージをブロックする

### lintパッケージに関係なく確認すべき主要ルール:
- [ ] `prefer_const_constructors` — ウィジェットツリーのパフォーマンス
- [ ] `avoid_print` — 適切なloggingを使用する
- [ ] `unawaited_futures` — fire-and-forgetの非同期バグを防ぐ
- [ ] `prefer_final_locals` — 変数レベルの不変性
- [ ] `always_declare_return_types` — 明示的なコントラクト
- [ ] `avoid_catches_without_on_clauses` — 具体的なエラー処理
- [ ] `always_use_package_imports` — 一貫したインポートスタイル

## 状態管理クイックリファレンス

以下の表は、普遍的な原則を人気のソリューションでの実装にマッピングしています。プロジェクトが使用しているソリューションに合わせてレビュールールを適応させるために使用してください。

| 原則 | BLoC/Cubit | Riverpod | Provider | GetX | MobX | Signals | Built-in |
|-----------|-----------|----------|----------|------|------|---------|----------|
| 状態コンテナ | `Bloc`/`Cubit` | `Notifier`/`AsyncNotifier` | `ChangeNotifier` | `GetxController` | `Store` | `signal()` | `StatefulWidget` |
| UIコンシューマー | `BlocBuilder` | `ConsumerWidget` | `Consumer` | `Obx`/`GetBuilder` | `Observer` | `Watch` | `setState` |
| セレクター | `BlocSelector`/`buildWhen` | `ref.watch(p.select(...))` | `Selector` | N/A | computed | `computed()` | N/A |
| 副作用 | `BlocListener` | `ref.listen` | `Consumer` callback | `ever()`/`once()` | `reaction` | `effect()` | callbacks |
| Disposal | `BlocProvider` で自動 | `.autoDispose` | `Provider` で自動 | `onClose()` | `ReactionDisposer` | manual | `dispose()` |
| テスト | `blocTest()` | `ProviderContainer` | `ChangeNotifier` 直接 | `Get.put` in test | store直接 | signal直接 | widget test |
